# GPT-6 火出圈后，再看物理世界里的 Agent

GPT-6 Astra 与 RoboCurve 合作的宣发前几天席卷具身圈。通用模型开始既能做相当不错的直接控制，也能和 π0.5 这样的 VLA 配合，令人欣喜。

当然，对于模型在物理世界中的能力，无论吹的多么花里胡哨，我都会回来关注这些要点：它能不能长时间自主做事（long horizon agentic 能力），能不能跟上真实世界的时间（实时性），以及，怎么知道自己刚才到底做对了没有（状态判断准确性，包括但不限于空间理解）。

最后这个问题是很多一直在做 VLM agent 的朋友一直关注的：物理世界中，机器人以为自己拿到了杯子，实际上夹爪是空的，如果没发现，后面的移动、倒水、放回就都接不上了。一次抓取失败通常还有办法补救，带着一个错误的状态判断继续做下去，问题会越来越多。这就像数字世界里的 Coding，最早程序员通过 chatbot 的方式与 coding LLM 对话，没有执行验证，合成的代码还需要经过程序员的执行与 debug 才能把问题闭环；而由于执行和验证的环境可以被构建，客观的中间执行步骤结果可以反馈给 agent，从而让它根据环境反馈进行重试与修正（try and error），自主解决问题。我们需要物理世界也能给这样的反馈——人类有时候可以通过其它路的输入，例如换个角度的视觉、换触觉等方式 double check，模型是否也可以通过调用别的 tool 或者利用别的来判断呢？这里留作一个 open question。

回来看引爆网络的那份 [GPT-6 与 π0.5 的报告](https://anonymous-report-421.github.io/public-website/?lang=zh&view=1)。首先 RoboDojo 差不多是现下最难的仿真操作类 benchmark——看官方榜单，在这次汇报之前的最高分还是 30 来分。
报告在 RoboDojo 里选了十个任务，混合架构的平均 Score 是 62.60，成功率 48%。但这是作者自测的任务子集，选题偏向 π0.5 原本做得不好的任务，每个任务只有五次实验；其他模型的数据来自公开榜单，按这个子集重新计算，没有在同样的种子上重跑。具体提升幅度，还有待 RoboDojo 官方榜单的刷新。

不过，即使先不讨论翻倍的幅度，这个结果也点燃了具身圈子的热情，（事实上以前我就一直好奇为啥没人用上层大模型 agent + VLA的方式刷这个榜单，现在果然有人做了）。它把两种能力的差异测出区分得挺清楚：语义、顺序、规则这类任务，GPT 会强很多；搭塔、麻将杠牌这类“contact rich”操作，专门训练过的控制策略仍然更稳。在另一个以语义 pick and place 为主的 RoboLab 测试中，GPT Direct 做到了 49/50，混合架构是 46/50。不过，这组实验的初态、预算和重试没有完全对齐，三条轨迹的差距还不足以说明加 VLA 一定有负面效果。（这里的 Direct 也有一个容易被名字盖过去的细节：GPT 输出的是末端目标，下面仍然有 IK 和控制器。它已经接管了更多决策，但距离直接负责所有底层控制，还有一段距离。）值得注意的是，大概也是源于为人所诟病的 VLA 的泛化难问题，RoboLab 任务里作对照的 VLA 没有做专门的对齐训练，且未可知在 Robodojo 与 RoboLab 中，VLA + agent，对比大模型 Direct 出策略的优劣，到底是因为任务类型差异，还是 VLA 是否专门针对性对齐过。

无论如何，这让我们不禁思考 GPT 到底在什么位置帮上了忙，具体来看看任务 setting。

报告中的混合架构会先让 π0.5 生成未来 50 个控制步的动作，再由 GPT 决定接受其中一小段（比如 15/50），或者自己给出修正。GPT 可以不接受这段动作，先改一下当前状态，再让 π0.5 重新生成。此前为人所诟病的VLA 泛化差的问题，也许有一部分可以从环境这一侧解决。比如之前目标物体在桌边，角度很别扭，旁边还有遮挡。直接把“抓起来”交给一个局部策略，它可能一直失败。但上层可以先挪开遮挡，把物体拨到更容易接近的位置，换一个观察角度，再交给 VLA。权重没有变，任务却变得像它见过的了。

我们通常把泛化理解为模型面对陌生状态仍然能做对。现在多了一种做法：agent 有能力把陌生状态变成熟悉状态。这当然有局限性——机器人够不着、力气不够、根本不会某个接触技能，都不能靠上层说几句话解决。但在可调整的范围里，组合系统能做的事情可能比任何一个局部策略单独做的都多。

[Harness VLA](https://arxiv.org/html/2607.08448v1)里用解析动作重新定位和接近、再交给冻结 VLA 处理局部接触的思路，其实也类似于这种尝试。它让我觉得，“底层技能的泛化必须和上层一样强”这个要求可以再讨论。底层可以窄一些，只要上层知道它擅长什么，也有办法把状态带过去。作者在社交媒体上也第一时间公开了他们方案接入 GPT-6 的惊艳效果。不过，按照 paper 里他们的 setting，每一步状态的判断（这一步完成没完成）还是依赖仿真环境给 GT；我们修改成模型自己判断，GPT-6 也能完成得很好，这说明在这类任务上，头部大模型对中间状态的观察和理解已经比较准确。

问题是，我们现在对这种操作和理解能力，到底准确到什么程度往往知道得不够清楚。

一个抓杯子的 skill，测试成功率可能很高。但它抓在杯口、杯身还是杯柄，对下一步的影响完全不同。都算“拿起来了”，有的方便倒水，有的方便递给人，有的会挡住后面的操作。把几个单项成绩不错的 skill 串起来，未必就能得到一个可靠的长程任务。

技能结束后把世界留成了什么样？这个状态能否接上下一个技能？中途打断时会不会松手？失败后物体大概去了哪里？这些信息如果没有进入工具接口，上层其实没有客观的答案。

[VLAs-as-Tools](https://arxiv.org/html/2605.13119v1)把训练目标向具体调用对齐，也加入执行过程中的反馈。VLA 成为工具以后，训练它的标准会发生变化：除了自己完成任务，还要让调用者知道它在做什么，并且让下一段动作接得上。它会被放弃作为一个“能执行很长任务的脑子”来训练的目标，而是作为单个原子任务的执行器——事实上工业界不少场合，大家也是这么做的。

contact rich 的任务仍然 VLA 这类专门策略的优势。摩擦、形变、滑动、被遮挡的接触状态，都会让单靠图像慢慢想再给末端目标变得困难。不过 VLA 的价值也不只在这里。它能用比较紧凑的表示、比较低的在线开销，持续处理一段动作。这种执行效率，即使通用模型的能力继续增强，也还有意义——GPT-6 作为巨大的模型，为一个简单动作消耗巨大的推力成本，以及承担巨大的时间消耗，都是在物理世界不现实的。

“Code as Policy”本身也有不同做法。每走几步都等模型重新想一次，和模型先写出一个能在本地高速运行的反馈控制器，时间开销很不一样。后者仍然有合成与验证的问题，但不能把两者都算成“大模型每个控制周期亲自思考”。

[Anthropic 的机器人实验](https://www.anthropic.com/research/claude-plays-robotics)里，LIBERO 直接操作和 VLA supervision 的两张结果图，我觉得适合放在一起看。直接操作的结果显示，基模进步确实开始带来更多控制能力，只是提升并不严格单调；VLA supervision 的结果又显示，上层乱插手，会把原本能成功的动作干扰掉。此前我把这个叫作 system-2 税。即使现在到了 GPT-6，我也还不敢认为这笔税已经消失了。

回到[GPT-6+VLA 的 RoboDojo 测试](https://anonymous-report-421.github.io/public-website/?lang=zh&view=1)：混合轨迹里，GPT 自己修改的控制步只占 14.4%；但不能据此说明剩下 85.6% 的任务贡献都来自 π0.5。
动作占比算不出贡献占比。一次很短的修正，可能让后面很长一段动作终于有机会成功。而且 GPT 在各个动作段的边界都参与判断，只是很多时候选择了沿用 VLA。没有修改动作，也已经付出了观察和决策的成本。

所以我很好奇：这些修改里，哪些纠正了语义目标，哪些调整了几何状态，哪些只是避免了一个即将发生的错误？如果在同一个状态下分叉，让系统分别继续原来的 VLA、只改局部指令、调整环境后再执行、直接接管动作，应该比单看 14.4% 更容易找到收益来源。这个角度看，昂贵的 GPT 也可以先当老师用。

值得留下来的不只是最后成功的轨迹，还有它什么时候发现不对、看到了什么、改了哪几步，以及什么时候觉得可以把控制权还给 VLA。

这和 [DAgger](https://arxiv.org/abs/1011.0686)关注策略执行后实际会遇到哪些状态，有相通的地方。只学顺利完成的演示，很容易漏掉部署时反复卡住的位置。当然，GPT 给出的修正也要由实际结果筛过，不能因为是更大的模型说的，就直接当成正确标签。

沿着 CaP-X、Harness VLA、VoLoAgent 到 Thea 看下来，我的关注点也逐渐从“模型能生成多底层的动作”，移到了“模型怎么持续参与任务”。当然，作为训 Code Agent 出身的，一上来就觉得 CaP-X 这种和物理世界交互稀疏的方案不够有品。

虽然[CaP-X](https://arxiv.org/html/2603.22435v1)已经包含多轮执行反馈和视觉差分，不能简单归为一次性生成代码，但它很大一部分问题意识，仍然围绕代码控制接口展开。[VoLoAgent](https://arxiv.org/html/2606.07723v1)进一步把执行中的监控做了进来：动作可以异步运行，上层观察后决定继续、打断或者恢复。这比调用一个工具后一直等它返回，更接近物理任务的需要。VoLoAgent 的 Monitor 步骤，把一部分自主控制权交给了 agent，让它初具 agentic 雏形——比较有缺憾的是，整体运行框架，Plan-monitor-replan 还是人为定死的，不完全由模型自主控制。

[Thea](https://arxiv.org/html/2608.11246v1)则更像自主的 Agentic 逻辑，并且它把导航、操作、与人交互放进了同一组工具里——任务范围终于可以走出台面上的 manipulation。不过，工具按轮次调用的方式，也保留了我们在 coding agent 上已经很熟悉的等待感——它的演示 demo 都是加速数倍或者几十倍的 case。

我仍然期待一种更像 SWE agent 的自主性：提供工具，让模型自己决定接下来做什么。只是“没有人手写任务流程”和“没有运行协议”，是两件事。哪些动作可以同时做、取消调用以后机器人到底停没停、旧指令会不会覆盖新状态，这些事总要有人管。把它们放进运行时，并不妨碍模型自由安排任务，似乎能让这种自由更可用。

时间问题就在这里变得严峻了。

GPT-6 + VLA 的 RoboDojo 测试报告里，混合架构平均一条轨迹用了约 1250 万 token，对应的机器人运动时间只有约 34 秒。第一眼确实很夸张，但这个数字也需要拆开：按[报告列出的用量](https://anonymous-report-421.github.io/public-website/?lang=zh&view=1)计算，约 97% 的总 token 量来自缓存输入。它不等于每条轨迹都新生成了 1250 万 token 的思考。实际开销还要看缓存计费、输出量，以及每次调用等了多久。

现有的分层具身解决方案，评测的设置是，模型思考时，仿真在等待。34 秒只统计控制步对应的物理时间，没有把模型响应的等待加进去。——现实里思考也是有客观的时间流逝的，环境不会因为你的思考而停止。

freeze 思考时环境事件的实验，能先回答模型在充足时间下的成功率；但真机上，东西会滑，人会走，其他设备还在运行。多想十秒可能得到一个更好的动作，也可能让刚才那个动作彻底失去意义——我们不能忽略这个延迟，这也是我们提出 [EP 交互](https://arxiv.org/abs/2605.11484)的动机。

Gemini Robotics ER 2 的[发布内容](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/gemini-robotics-er-2/)很重视持续视频和执行监控，这个方向我认同。不过，常说的“1 Hz 上层大脑”还需要留一点余地。[接口文档](https://ai.google.dev/gemini-api/docs/robotics-streaming)说的是视频输入最多 1 FPS，视频帧本身不触发响应，示例里的 heartbeat 还会等上一轮完成。所以，每秒送一帧，不等于每秒一定能完成一次判断。

有趣的是，即使普通 Gemini，也有更喜欢短调用、更多轮的倾向，[CursorBench 4.0](https://prod.cursor.com/evals)也给了一部分支持：Gemini 3.8 Flash High 平均用了 324 步。但步数多还不能推出实时性好。每次调用短一些，可能更早获得新反馈，也可能只是多了很多等待和重复观察；coding harness 里的行为，也不一定能直接迁移到机器人。

他们目前方案大题还是基于 turn based——如果一个 tool call turn 的推理 decoding 没完成，那么外界出现的预警观测也不会进入；而我们期待的是一种完全不阻塞的交互模式。不知道未来是否能**把 thinking 和 action 完全解耦，变成多流并行的架构**。

这里也不能只等上层推理越来越快。很多状态没什么新信息，重复请大模型看一遍很浪费；有些变化却不能等下一轮长思考结束。我们需要决定什么时候值得多想，什么时候先执行，什么时候让新的观察打断还没用上的旧计划。——或许这种监控类的流，也适合某种类似于 KV Cache 压缩的机制。早先我做 KV Cache 压缩的时候，普遍被圈内人意识到的点就是 attention 是十分稀疏的，在文本 context 里如此，视频流里更如此（考虑到人类的视觉体验，视频的空间冗余和时间轴上的冗余一定更多）。或许也值得训练一个感知头，用来检测和做视频流输入的稀疏化或者压缩，而非使用启发式的 1hz 2hz 输入到上层大模型。

如果需要这种压缩机制，那么我们就需要能评估，减少监控以后，最先漏掉的是哪些错误的评测方案，类似于做量化或者剪枝后，模型能力是否有损的凭据。

底层也有类似的实时性问题。Physical Intelligence 的 [Real-Time Chunking](https://www.pi.website/research/real_time_chunking)讨论了如何在旧动作还在执行时生成新动作，并让两段衔接起来。这让人关注到，异步执行不只是把请求提前发出去，因为新策略接手时，机器人已经走到了一个新的状态，而推理延迟会改变动作生成的先验。

这些事情最终可能装进同一个模型，也可能分布在几个模型和控制器里。我暂时不太执着思考参数放在哪里。只要世界还在动，慢规划和快反馈之间的关系就仍然要处理。

最后还是回到绕不开的问题：谁来告诉 agent 它做对了没有？

SWE agent 给我们的启发很直接。早期是人把代码贴进环境里跑，看到错误再回头问模型；后来 agent 自己运行、读错误、修改，很多能力才在这个循环里用起来。物理 agent 能不能也有一个类似的 verifier？我觉得还是要有，但未必是另外放一个大模型。

代码执行本身也不保证需求完成，退出码正常、测试通过，都只覆盖了某些性质。放到机器人上，这个区别更明显：到达目标位姿不代表夹住了物体，夹爪闭合不代表东西没滑走，插头看起来插好了，也不代表已经导通。

GPT-6 判断空间状态的能力提升，显然会缓解很多问题。但 RoboDojo 测试报告中还有一个细节：模型会注意到仿真器没有终止，进而怀疑还有条件没有完成。这是很好的利用反馈的能力，却也说明，环境仍在告诉它“还没成功”。完全拿掉这个信号后，它能不能同样可靠地判断结束，还需要另外测。

Thea 已经尝试用[独立的评价环节](https://eit-hai.github.io/thea/documentation/evaluation/index.html)，根据执行后的新观测和工具后置条件判断结果。把评价和行动模型的自我报告分开，我觉得有用。否则模型刚刚花了很多精力执行自己的计划，遇到模糊画面时，很容易顺着“应该已经成功了”往下理解。

不过，两个模型看同一张遮挡严重的图，也可能一起猜错。有些问题根本没有足够的信息：物体是不是被压住了，接触面有没有打滑，插头有没有导通，光靠当前图像就分不出来。换一个更大的模型，并不会自动多出这些证据。

这时需要的可能是换个角度看，读一下力信号，检查电气连通，或者轻轻移动一下，看物体是否真的跟着夹爪走。独立验证最有用的部分，往往是带来另一种多角度证据，而不只是另一份同样先验的判断。

继续大胆设想，验证其实可以提前参与规划。

同样是把物体放进去，一条路线最快，但最后物体被完全挡住了；另一条稍微绕一点，完成后还能看到关键部位。只比较动作是否成功，两条路线也许差不多。但如果后面还有很多步骤，第二条可能更值得选，因为它更容易确认，也更容易在出错时补救。

参考之前报告中的“把物体拨到一个 VLA 熟悉的位置”，也可能同时把它拨到了一个更容易观察的位置。动作能力和判断能力在这里是连着的。上层规划时，就可以把后面怎么确认、失败了怎么收拾一起考虑进去。可以考虑一个很直接的实验：任务目标相同，只改变不同路线完成后的可观察程度，看 agent 会不会主动选择更容易确认结果的做法，以及这是否真的提高了后续任务的成功率。

仿真 GT 当然还要留。它适合做训练信号，也适合检查 verifier 到底判断得准不准。但如果最后想用到真机上，就应该有一组运行时看不到 GT 的实验。连“说完成后仿真器还没退出”这样的隐含反馈，也要一起控制。

可以先固定上层和执行器，分别用 GT、上层自判断、独立视觉判断、加入额外传感或主动观察的判断来跑。再把暂停的仿真换成持续运行的仿真。这样才比较容易知道，系统缺的是理解能力、观察证据，还是来不及反应。

评测本身也要有点新活。[What Are We Actually Benchmarking in Robot Manipulation?](https://arxiv.org/html/2606.04233v1)用 DINOv2+MLP 和任务 ID，在 LIBERO 的一些子集上拿到了很高的分数。这个结果提醒我们，高分未必检验到了语言理解，暴论是：训一个有题目先验的 action sequence 分类器似乎对这类早期 benchmark 就很有效了，那么 language backbone 到底起什么作用？这么多来自数字世界的训练成果，真的有被好好用上吗？

对我们想做的 agent，也有同样的问题。把固定流程拉长，未必就在测自主性。更难得的问题是：同一个场景里换了目标，某个工具突然不能用了，上一个动作留下了不理想的状态，或者人中途改了要求，它还能不能把事情接着做下去。

所以，我还是比较认可“通用大脑可能不用从头造了”。至于具身上层是不是因此没有训练空间，我觉得还远没到可以下结论的时候。何时相信工具，何时承认证据不足，何时放弃已经想了一半的计划，这些都可以是训练目标。具身的研究人员们在大模型这一测也还需要思考数据以怎样的方式灌入，训练目标怎么设置比较好。或许 pretrain 又是简单粗暴堆量 ego 数据的 fill in the middle 吗？用什么来填空呢？

即便上层暂时很贵，只要确实能做好，就可以先用它收集干预和恢复数据，再把常见部分交给便宜的策略；难例再叫回来。这条路能否形成持续改进，要看反馈是否可靠。生成动作和给动作打分如果一直互相认可，离真正变好还差一次外部检验。

所以我们现在比起 demo，更想看的是机器人连续做几个小时的，不可约的事——跑马拉松和分拣差不多大小的快递算压测，我没那么感兴趣。GPT-6 让这种期待更接近现实了。且看接下来它能带我们走到多远；同时，我觉得轻量化以应对实时性的大脑模型，依然更有吸引力。感觉业界需要更多关注 Gemini 的相关工作。
